# Evaluation boundaries

The frozen instrument release contains 388 MCQA questions and 120 sequential tasks. Public observations, manuals and offered commands are model inputs. Answer keys, scheduled faults and grading fixtures remain evaluator-only.

MCQA evaluates selection of an original option. Feature fitting uses training data and any declared tuning uses validation data; held-out questions measure generalization of fitted methods. Complete-cohort hosted MCQA is reported separately in the final report.

Free-run evaluates an autonomous trajectory with the consequences of its actual actions. Teacher forcing first grades the original proposal, then applies an accepted reference action when required. Subsequent decisions receive the corrected state and feedback. Assisted completion therefore differs from autonomous success. A failure before a native proposal cannot be repaired by teacher forcing.

The local graph supports bounded public decision views, optional guided JSON and deterministic procedure envelopes. Hosted evaluation uses a generative procedure role. Record these protocol choices and model context settings with each study.

Preserve failed attempts, missing cases and original proposal counts when calculating metrics. Separate model output/call errors, interface defects and external service failures. Report no action accuracy where there were no observable proposals. Probability vectors are not automatically calibrated estimates of whole-task success.

Native simulation and rubric consistency do not establish physical laboratory safety or exhaustive scientific validity. The browser review tools support independent assessment. Source manifests authenticate the release bytes; they do not establish correctness of the scientific rubric.
